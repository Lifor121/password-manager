# Миграции базы данных (Alembic)

## Описание
Эта папка содержит миграции базы данных для менеджера паролей, созданные с использованием Alembic.

## Команды

### Инициализация Alembic
```bash
# Установите зависимости
pip install alembic asyncpg psycopg2-binary

# Создайте первую миграцию (если еще не создана)
alembic revision --autogenerate -m "Initial tables"
```

### Применение миграций
```bash
# Применить все миграции
alembic upgrade head

# Откатить последнюю миграцию
alembic downgrade -1

# Применить конкретную миграцию
alembic upgrade 001

# Проверить текущую версию
alembic current

# Показать историю миграций
alembic history
```

### Создание новой миграции
```bash
# Автогенерация миграции на основе изменений моделей
alembic revision --autogenerate -m "Description of changes"

# Создание пустой миграции для ручных изменений
alembic revision -m "Description of changes"
```

## Структура миграций

### Существующие миграции

#### 001_initial_tables.py
- Создание таблиц `users`, `sessions`, `vault_items`
- Создание индексов для оптимизации запросов
- Установка внешних ключей с каскадным удалением

## Принципы работы

1. **Autogenerate**: Alembic сравнивает текущие модели SQLAlchemy с состоянием базы данных
2. **Миграции**: Каждая миграция содержит методы `upgrade()` и `downgrade()`
3. **Версионность**: Миграции применяются последовательно, поддерживается откат

## Важные замечания

### Безопасность данных
- Миграции не должны содержать чувствительных данных
- Тестовые данные загружаются отдельным скриптом
- Все операции должны быть обратимыми (иметь `downgrade`)

### Разработка
1. Внесите изменения в модели SQLAlchemy
2. Запустите `alembic revision --autogenerate -m "описание"`
3. Проверьте сгенерированную миграцию
4. Примените миграцию: `alembic upgrade head`
5. Протестируйте изменения

### Продакшен
1. Все миграции должны быть проверены перед применением
2. Создавайте резервные копии перед применением миграций
3. Тестируйте миграции на staging-окружении
4. Используйте `alembic upgrade` в процессе деплоя
